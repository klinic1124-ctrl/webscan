# 0단계 검증 보고서

계획서(`docs/scanner-plan.html`)의 0단계 목표는 "브라우저 안, 서버 없이 OpenCV.js로 검출 · 원근 보정 · 조명 균일화가 실기기에서 충분히 빠르게 도는지" 확인하는 것이다. 이번 빌드는 그 검증용 프로토타입이다.

결정 사항(2026-11-05): 웹 전용, 서버 없음, React, 앱스토어 배포 없음. 주 대상은 서류, 악보, 사진이다.

## 구현 범위

| 단계 | 내용 | 파일 |
|---|---|---|
| S1 입력 | EXIF 방향 반영 해독, 긴 변 4000px 상한, 1600px 미리보기 | `src/scanner.ts`, `src/worker/scanner.worker.ts` |
| S2 경계 검출 | 3가지 후보 경로(약한 엣지, 강한 엣지, Otsu 밝기 분할) → 볼록성·각도·면적·**엣지 일치율**로 점수화 → 변마다 엣지 픽셀 직선 맞춤으로 꼭짓점 정제 | `src/lib/cv/pipeline.ts` `detectQuad` |
| S3 수동 조정 | 꼭짓점 4 + 변 4 핸들, 드래그 중 3배 돋보기(손가락 반대쪽), 자동 검출 / 전체 선택 / 90° 회전 | `src/components/CropEditor.tsx` |
| S4 원근 보정 | Zhang & He 방식으로 초점거리와 실제 종횡비 추정(소실점이 하나뿐이면 26mm 상당 렌즈 가정), A4·B5·Letter 프리셋 | `src/lib/geometry.ts` `estimateAspect` |
| S5 조명 균일화 | 닫힘 연산으로 종이 배경 추정 → 채널별 나눗셈 | `estimateBackground`, `flattenIllumination` |
| S6 반사광 | 하얗게 날아간 영역 비율 측정 후 1.5% 넘으면 재촬영 안내(복원은 2단계) | `saturated` |
| S7 마무리 | 컬러 / 회색조 / 흑백(Sauvola + 잡점 제거) / 사진(L 채널만 약하게) / 자동 판별 | `finishDocument`, `binarize`, `enhancePhoto`, `classifyPage` |
| 계측 | 단계별 시간, 3회 벤치마크, WASM 메모리, 결과 JSON 복사 | `src/App.tsx` |

## 자동 테스트 결과 (합성 사진, `npm test`)

카메라 모델로 A4 문서를 투영해 만든 "휴대폰 사진"(나무 책상, 조명 기울기, 손 그림자, 센서 잡음, 선택적 반사광)으로 정답과 비교한다. 39개 테스트 모두 통과.

- **경계 검출**: 서류·악보·사진 × 4가지 자세(강한 원근, 25° 회전, 소실점 1개 등) 12건 모두 꼭짓점 오차가 대각선의 0.5% 이내다(실측 약 1~2px / 2000px). 문서가 없는 사진은 "못 찾음"으로 보고된다.
- **종횡비**: 4가지 자세 모두 A4 비율과의 차이가 2% 이내다. 단순히 변 길이로 계산하면 40° 기울기에서 15% 가까이 틀리는 것과 비교된다.
- **조명 균일화**: 그림자 있는 종이 배경의 밝기 표준편차가 약 32에서 약 1.7로 줄고, 평균은 254다.
- **흑백**: 원본 페이지와 픽셀 일치율 97% 이상(서류, 악보). 오선과 기둥이 유지된다.
- **자동 판별**: 서류·악보는 회색조, 사진은 사진 모드(그림자 유무 모두).
- **메모리**: 같은 작업을 반복해도 WASM 힙이 늘지 않는다(누수 없음).

## 속도 (개발 서버 기준, 휴대폰 아님)

Xeon 2.1GHz 4코어, Node/Chromium. **실기기 수치가 아니므로 휴대폰 측정이 꼭 필요하다.**

| 항목 | 1.9MP 사진 (브라우저) | 12MP 사진 (Node) |
|---|---|---|
| 엔진 준비(다운로드 후) | 약 125 ms | – |
| 경계 검출 | 130~200 ms | 173 ms |
| 스캔(회색조) 합계 | 175~225 ms | 약 570 ms |
| 스캔(사진 모드) | – | 약 860 ms |

## 확인된 사항과 다음 조치

1. **OpenCV.js 공식 빌드는 SIMD와 스레드가 꺼져 있다.** 크기는 10.8MB(WASM 내장)다. 1단계에서 필요한 모듈만 넣고 SIMD를 켠 맞춤 빌드를 만들면 크기와 속도 모두 개선될 여지가 크다.
2. **원형 커널 모폴로지는 사각 커널보다 약 15배 느렸다(511ms 대 33ms).** 배경 추정은 사각 커널과 저해상도 블러로 바꿔 10배 빨라졌다.
3. **OpenCV.js 모듈 객체에는 `then` 메서드가 있다.** 그래서 `async` 함수에서 반환하거나 동적 `import()`로 불러오면 영원히 멈춘다. 초기화 후 `then`을 지우도록 `loadCv`에서 처리했다.
4. **Sauvola 이진화는 큰 검은 면(제목 막대, 굵은 빔)의 속을 비운다.** 조명을 편 뒤에는 중간 회색보다 어두우면 무조건 잉크로 보도록 보완했다.
5. **사진 모드는 그림자를 일부러 약하게만 보정한다.** 사진 자체의 어두운 영역과 그림자를 구분할 수 없기 때문이다. 손 그림자가 진한 사진은 남는다(2단계에서 다중 촬영이나 사용자 브러시 검토).
6. **메모리**: 12MP 원본 1장이면 WASM 힙에 RGBA 48MB가 든다. 흑백 모드는 float32 버퍼 4개(페이지 4MP 기준 약 64MB)를 더 쓴다. iPhone Safari에서 실제 한도를 측정해야 한다.

## 실기기 측정 방법

1. `npm install && npm run build && npm run preview`를 실행하고 휴대폰에서 같은 네트워크 주소로 접속한다. 카메라 촬영에는 HTTPS가 필요할 수 있으니, 정적 호스팅(Cloudflare Pages 등)에 `dist/`를 올리는 편이 가장 간단하다.
2. 서류 3장, 악보 3장, 사진 3장을 각각 책상 위에서 촬영한다(밝은 책상 1회 포함).
3. 각 장마다 **스캔하기 → 벤치마크(3회 반복) → 측정 결과 복사**를 누르고 JSON을 모은다.
4. 자동 검출 후 핸들을 움직여야 했는지 기록한다(1단계 목표: 수정 없이 통과 80%).

완료 기준: 중급 Android와 iPhone에서 1장 스캔(검출 + 스캔) 2초 이내, 강제 종료 없음.
