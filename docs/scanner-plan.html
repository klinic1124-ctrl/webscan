개발 계획서 · v0.1 초안

웹 문서 스캐너 개발 계획서

휴대폰 카메라로 찍은 문서·그림·사진을 평판 스캐너로 스캔한 것처럼 바꿔 주는 모바일 웹 앱. 문서 영역 자동 검출과 사람의 최종 미세 조정, 원근 왜곡 보정, 그림자·반사광 등 명암 불균일 제거를 거쳐 이미지 또는 PDF로 저장합니다.

작성일 2026-11-05 대상 iOS Safari · Android Chrome · 데스크톱 형태 PWA (설치형 웹앱)

요약핵심 결정

권장 방향: 서버 없이 브라우저 안에서 모든 영상 처리를 수행하는 PWA로 개발합니다. 처리 엔진은 OpenCV.js(WebAssembly)를 Web Worker에서 돌리고, UI는 React + TypeScript + Vite로 만듭니다. PDF는 pdf-lib로 브라우저에서 직접 생성합니다.

이유: 사진이 기기 밖으로 나가지 않아 개인정보 부담이 없고, 서버 비용이 들지 않으며, 오프라인에서도 동작합니다. 앱스토어 배포가 필요해지면 같은 코드를 Capacitor로 감싸 iOS/Android 앱으로 낼 수 있습니다.

범위 주의: 그림자·조명 얼룩 제거는 단일 사진으로 안정적으로 해결됩니다. 그러나 광택지의 강한 반사광(글레어)은 해당 부분의 정보가 사진에 아예 없기 때문에 한 장으로는 완전히 복원할 수 없습니다. 각도를 바꿔 2~3장을 찍어 합성하는 기능을 2단계에 넣는 것을 권장합니다.

03영상 처리 파이프라인

검출과 분석은 축소본(긴 변 약 1,000px)에서 빠르게 하고, 결과 좌표를 원본 해상도에 적용해 최종 이미지를 만듭니다. 주황색 단계는 사용자가 개입하는 지점입니다.

S1

입력과 정규화

EXIF 방향 보정, 긴 변 4,000px 상한으로 리사이즈(iOS 캔버스 면적 한도 약 16.7M 픽셀 대비 여유 확보), 분석용 축소본 생성.

createImageBitmap(file, {imageOrientation:'from-image'}) → resize → gray(1000px)
S2

문서 경계 검출

여러 후보를 만들고 점수로 고릅니다. 후보는 엣지 기반과 색 분할 기반 두 경로로 생성하고, 면적 비율·볼록성·꼭짓점 각도(60~120°)·대변 길이 비율로 점수를 매깁니다. 실패하면 이미지 전체를 기본값으로 둡니다.

GaussianBlur → Canny(자동 임계값: 중앙값 ±33%) → morphologyEx(CLOSE) → findContours → approxPolyDP(ε=2% 둘레) → 4점 후보 점수화
보조: LAB 변환 → k-means(2) 또는 GrabCut으로 종이 영역 → minAreaRect / 꼭짓점 정제(cornerSubPix)
S3

사람의 미세 조정

네 꼭짓점과 네 변 중앙에 핸들을 둡니다. 손가락이 꼭짓점을 가리므로 드래그 중에는 손가락 위쪽에 3배 확대 돋보기를 띄웁니다. 핸들 근처의 강한 엣지 교차점으로 살짝 끌어당기는 스냅, 오목한 사각형 경고, 되돌리기를 제공합니다.

S4

원근 보정

네 점으로 호모그래피를 구해 원본 해상도에서 펼칩니다. 출력 비율은 용지 프리셋을 쓰거나, 자유 모드에서는 카메라 초점거리 추정으로 실제 종횡비를 계산합니다(Zhang & He 화이트보드 정류 방식). 단순히 변 길이로 계산하면 비스듬히 찍은 문서가 눌려 보이기 때문입니다.

getPerspectiveTransform(src4, dst4) → warpPerspective(INTER_CUBIC, BORDER_REPLICATE)
S5

조명 균일화 (그림자·얼룩 제거)

종이 배경의 밝기 분포를 추정한 뒤 원본을 배경으로 나눠 평탄하게 만듭니다. 글자처럼 가는 획은 큰 커널의 닫힘 연산에서 지워지므로 배경만 남습니다. 컬러는 LAB의 L 채널에만 적용해 색이 틀어지지 않게 합니다.

L 채널 → 축소 → morphologyEx(CLOSE, 커널≈문서폭/30) → medianBlur → 확대 = 배경 B → L' = L / B × 255
S6

반사광(글레어) 처리

밝기가 포화되고 채도가 낮은 영역을 반사광으로 판정해 마스크를 만듭니다. 단일 사진에서는 작은 반사만 주변으로 메우고(inpaint), 큰 반사는 사용자에게 "다른 각도로 한 장 더"를 안내합니다. 다중 촬영 모드에서는 각 사진을 같은 평면으로 정합한 뒤 픽셀별로 반사가 없는 쪽 값을 고릅니다.

mask = (V > 245) ∧ (S < 25) → dilate → 단일: inpaint(TELEA) · 다중: ORB 특징 → findHomography(RANSAC) → 픽셀별 최소 밝기/가중 합성
S7

모드별 마무리

컬러 문서: 종이 픽셀 기준 화이트밸런스, 흰색 클리핑, 약한 언샤프 마스크. 흑백: Sauvola 적응형 이진화, 잡점 제거. 사진·그림: S5를 약하게만 적용하고 색과 계조를 보존, 자동 레벨만 조정. 자동 모드는 채도·엣지 밀도로 문서/사진을 판별합니다.

S8

검토와 내보내기

모드 전환과 밝기·대비 슬라이더로 결과를 확인하고, 페이지 순서를 바꾼 뒤 이미지나 PDF로 저장합니다.

04시스템 구조

무거운 영상 처리는 모두 Web Worker로 보내 UI가 멈추지 않게 합니다. 데이터는 기기 안의 IndexedDB에만 저장합니다.

처리 원본과 사용자가 조정한 꼭짓점·모드를 함께 저장하므로, 나중에 다시 열어도 원본에서 재처리할 수 있습니다(비파괴 편집).

06화면 흐름

1 · 촬영

큰 촬영 버튼, 갤러리 버튼. MVP는 <input type="file" capture="environment">로 기기 기본 카메라를 열어 최대 해상도와 자동 초점을 그대로 활용합니다. 2단계에서 실시간 테두리 표시 카메라 화면을 추가합니다.

2 · 영역 조정

자동 검출된 사각형이 표시된 상태로 열립니다. 꼭짓점 드래그 + 돋보기, 회전, "전체 선택", 용지 비율 선택. 확인을 누르면 펼쳐진 결과로 넘어갑니다.

3 · 보정 결과

모드 칩(자동 · 컬러 · 회색 · 흑백 · 사진)과 원본 비교 토글. 반사가 감지되면 "다른 각도로 한 장 더 찍기" 안내가 뜹니다.

4 · 페이지와 저장

썸네일 목록에서 순서 변경·삭제·다시 자르기. 저장 형식(JPG / PNG / PDF), 품질(표준 150dpi / 고화질 300dpi), 파일 이름을 고르고 공유 시트로 저장합니다.

참고로 A4(210×297mm)를 300dpi로 출력하면 2,480×3,508px이 필요합니다. 12MP 휴대폰 사진에서 문서가 화면의 70% 정도를 차지하면 약 250~300dpi에 해당하므로, 업스케일 없이 원본 해상도를 최대한 살리는 것이 중요합니다.

개발자 1명 기준 추정입니다. 2명이면 UI와 처리 엔진을 병행해 약 30% 단축할 수 있습니다.

09위험 요소와 대응

위험대응
iOS Safari 메모리 한도로 탭이 강제 종료입력 상한 4,000px, OpenCV Mat.delete() 철저 관리(래퍼로 자동 해제), 페이지 결과는 즉시 Blob으로 IndexedDB에 저장 후 메모리 해제
흰 책상 위 흰 종이 등 저대비 배경에서 검출 실패색 분할 후보 경로 추가, 2단계 딥러닝 보조, 촬영 화면에 "어두운 배경 위에 놓으면 더 정확합니다" 안내
강한 반사광은 단일 사진으로 복원 불가반사 감지 시 재촬영·다중 촬영 유도. 기대치를 화면 문구로 명확히 전달
